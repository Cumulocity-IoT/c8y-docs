## Messages

The "Messages" usage metric for a given billing period (calendar month) is determined as the maximum of:
1. The total count of all data transactions to and in the Cumulocity platform, or
2. The total count of messages processed through the MQTT Service.

A data transaction is defined as any authenticated API request with the intention to create, update, or process data within the Cumulocity IoT domain model, including inventory objects, operations, measurements, events, and alarms. Transactions are counted regardless of processing mode, the details of which can be found in the [Tecnical Concept section of the Cumulocity documentation](https://cumulocity.com/docs/concepts/realtime/#implementation). Transactions originate from both internal and external sources, including other Cumulocity IoT applications, and are recorded via the platform’s [Usage Statistics API](https://cumulocity.com/api/core/#tag/Usage-statistics).

The total count of MQTT messages is metered daily via the MQTT Service, with each day's count contributing to the cumulative total for the billing period.

All counted transactions and messages are subject to the quotes listed in the [Service Quotas](https://cumulocity.com/docs/service-terms/quotas/) section of the Cumulocity documentation. Usage that exceeds the listed limits may result in additional charges to ensure platform stability and prevent abuse.

For each billing period, the sum of daily MQTT message counts and the total count of data transactions are separately calculated. The greater of the two values is used as the final invoiced metric, rounded up to the nearest 100,000 units. In the case that one of the values is unable to be computed, the other value will be used for billing purposes. 

### Example
During a billing period, the sum of the daily values for each of the referenced components are as follows:
* Data Transactions = **1,192,000**
  * Measurements Created = 1,000,000
  * Events Created = 20,000
  * Events Updated = 5,000
  * Alarms Created = 10,000
  * Alarms Updated = 5,000
  * Operations Created = 1,000
  * Operations Updated = 1,000
  * Inventories Created = 100,000
  * Inventories Updated = 50,000
* MQTT Messages = **200,000**
The total data transactions value is higher than that of the MQTT messages and therefore will be used as the final invoicing metric. To calculate the billable units, the total data transactions is rounded up the 100,000 units:
_1,192,000 / 100,000 = 11.92_
11.92 rounds up to **12 billable units** of Messages for the billing period. 

## GiB for Operational Data Store

The total volume of data stored in the Operational Data Store of the Cumulocity platform within a given billing period (calendar month). ODS is counted and exposed via the [Usage Statistics API](https://cumulocity.com/api/core/#tag) provided by the platform. The maximum daily value taken during the billing period will be used for invoicing purposes and is rounded up to the nearest gibibyte (GiB). A ‘gibibyte’ is defined as 1,073,741,824 bytes. A gibibyte may be colloqually referred to as a gigabyte and these names should be treated as the same value. 

## Tenant

Tenants are physically separated data spaces with a separate address (URL), with a specific set of users, a separate application management, and other individual functionality. Users in a single tenant share the same URL and the same data space. Add-Ons that use the per-tenant billing metric will be invoiced based on the number of tenants that have the Add-On deployed. 

## Cumulocity Compute Unit (CCU)

A Cumulocity Compute Unit (CCU) represents a standardized measure of computational resources consumed by microservices developed and deployed by the Customer, where 1 CCU is equivalent to 1 CPU core and 4 gibibytes (GiB) of memory. CCUs are calculated monthly by computing the daily average CPU consumption and daily average memory consumption (in bundles of 4 GiB) and taking the larger of the two values. This unit will be rounded up if fractional CPU cores or multiples of 4 GiB RAM are used. For example, 1.5 cores and 6 GiB RAM would be considered 2x compute units. Resource usage is first aggregated across all tenants before calculating the CCUs. A complete service description for Customer microservices can be found in the [Service Terms section](https://cumulocity.com/docs/service-terms/service-level/#microservices-sla) of the Cumulocity documentation. A ‘gibibyte’ is defined as 1,073,741,824 bytes.

### Example
The following aggregate metrics are calculated by summing up the daily resource limits for each custom microservice over the billing period (the documentation for the 'resources' field in the microservice manifest files can be found in the [Cumulocity documentation](https://cumulocity.com/docs/microservice-sdk/general-aspects/#settings). Custom microservices from all tenants across the Customer's deployments are included in this calculation. Cumulocity provided microservices are not counted as part of the custom CCU calculation.
* Aggregate CPU = 582,933
  * This metric is the total CPU time in millicores that is enabled for custom microservices. The metric is determined by the resource limits as written in the microservice manifest and the active subscription time of the microservice. 
* Aggregate Memory = 596,951
  * This metric is the total RAM allocation in Megabytes that is enabled for custom microservices, as determined by the resource limits in the microservice manifest.
 
To calculate the CCU billing metric, these values are converted to daily average. For the purposes of this example, the billing period has 30 days. 
_AvgCPU = (582,933 millicores / 30 days) = 19,431.1 millicores/day_
_AvgRAM = (596,951 MB/ 30 days) = 19,898.37 MB/day_

These daily average values are then put in the proper units aligned with the billable metric (CPU cores and GiB, respectively).
_ccuCPU = (19,431.1 millicores/day) / (1000 millicores) = 19.43 CPU/day_
> where 1000 millicores = 1 core
_ccuRAM = (19,898.37 MB/day) / (4294.97 MB) = 4.63 4GiB bundles/day_
> where 1 Gibibyte (GiB) = 1024 Mebibytes (MiB) = 1073.74 Megabytes (MB)
> 4 GiB = 4 * (1073.74 MB) = 4294.87 MB

Then, the larger of the two values is rounded up to form the CCU billable metric. 
_ccuCPU = 19.43 > 4.63 = ccuRAM_
19.43 rounds up to **20 billable units** of CCUs in the billing period. 




## DataHub - GiB of Data Queried

Gigabyte (GiB) of data read from data lakes or other supported data sources by the licensed DataHub software that falls into its 10 MB size minimum. The minimum size is 10 MB. For exceeding the minimum, values will be rounded up to the nearest Gigabyte. A gigabyte is defined as 1,073,741,824 bytes.

## DataHub - Memory Unit

A memory unit is defined as the memory allocation that may be assigned to a computational process or a container within the DataHub cluster that operates as either a co-ordinator node or worker node. Each container will consume a minimum of 4 GiB of memory. On a Cloud Platform, a container or host be deployed with no less than 10 GB of memory. The memory allocation will be split between container and executor memory according to the container size.
